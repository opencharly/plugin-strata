# 2026.290.1034 — docs(plugin-strata): state the runtime precondition — this plugin is a client

## Summary

States the plugin's **runtime precondition** in the plugin itself: `plugin-strata` is a **client**. It reaches a
deployed strata server over HTTP and reads the key catalogue from `GET /config`, so nothing here works until such
a deployment is running and reachable — and the plugin itself needs no model and no GPU. The real-engine proof
lives in the layer repo's `check-strata-gpu-pod`, which names a venue and pre-staged weights rather than
downloading (ledger §57). Stated beside the plugin block because *"the CLI over HTTP"* otherwise reads as
self-contained.

This is cutover 2's change, and it lands through a PR like the layer's did.

**Round 2 also fixes a defect this head carried.** `ci.yml` was copied from another repo's shell when this repo
was scaffolded (commit `da3deb8`, whose own message says INCOMPLETE) and pointed at `candy/plugin-qdrant` — a path
that does not exist here — so the head ran a **red** `ci` check:

```
##[error]The specified go version file at: candy/plugin-qdrant/go.mod does not exist
```

The first repair swept the **paths** (`candy/plugin-qdrant` → `candy/plugin-strata`, six of them) but **not the step
NAME**, which still read `tests (live qdrant test skips without a binary)` — a stale claim about another repo's test
surviving the very commit meant to sweep it. The review caught that (R5/CONC(c)); the name now describes this repo's
own test, and `grep -rc qdrant .github/workflows/ci.yml` is **0**. The two `qdrant` mentions left elsewhere in the
repo *cite* `plugin-ollama`/`plugin-qdrant` as the convention being mirrored, which is a reference, not a stale
claim. Found by reading the red check rather than only the required one.

**Disclosure, same as the layer repo's first landing.** `main` here already contains the repository's initial
contents — verified: the bootstrap created `main` from the default branch, which my push had made
`feat/plugin-strata`. That is the org's own flow, not an avoidable ordering mistake: the bootstrap's script
adopts the default-branch head, and an empty repo has none (measured — a bootstrap against the empty
`plugin-strata` reported `completed/success` while creating **nothing**, so `main` appeared only after a branch
existed). The mitigation is what I did: a fresh branch carrying a real change, and this disclosure, so the
unreviewed inherited content is on the record rather than asserted away.
